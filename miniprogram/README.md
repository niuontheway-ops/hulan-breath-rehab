# 壶兰呼吸微信小程序

版本：1.0.0。患者端原生项目，使用 WXML、WXSS 与微信原生 API，不通过 web-view 加载网页。健康数据保存在患者手机本机，不使用云开发、健康上传接口、业务登录或跨设备同步。

## 导入与预览

1. 在电脑安装并打开[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
2. 选择“导入项目”，选择本文件夹，确保能看到 `project.config.json`；不要只选择内部 `app` 文件夹。
3. 当前配置使用 `touristappid` 占位。没有 AppID 时，按开发者工具提供的测试号或游客入口进行本地开发；不要填写其他人的 AppID。
4. 不选择云开发。项目不需要云环境、数据库、云函数、业务服务器或 npm 运行依赖。
5. 导入后从首页开始检查健康评估、每日评估、训练、学习和本机记录。项目资源已生成，直接导入不需要先运行 Node 或 FFmpeg。

本工程不包含正式小程序码。要在患者微信中扫码体验或公开使用，需注册运营方自己的小程序，绑定 AppID 和开发者，完成隐私声明、主体与服务类目核对，再用开发者工具预览、上传、设置体验版或提交审核。不能把网页二维码或普通下载链接当作已经发布的小程序。

## 患者功能

- 健康评估按步骤填写，从年龄、疾病和当前状态开始；专业评分和肺功能可跳过。跳过不表示结果正常，也不自动开放训练。
- 康复教育沿用原项目的成人安全规则，区分稳定、加重后稳定、仍不稳定与危险症状。未获医护允许、资料不足或当前异常时，先复核。
- 训练使用人物示范、想象台阶、草地慢行三种场景；嘴部、腹部和手部随节拍变化。默认吸气约 2 秒、呼气约 4 秒，不强迫深吸或屏息。
- 每轮结束由患者主动确认。离开页面或进入后台立即暂停，返回后重新确认当前状态；不自动补计轮数，不读取麦克风或传感器来猜测呼吸。
- 每日评估保留 12 个疾病或支持主题；已有 ACT、CAT、ESS、FTND 总分可以选填，保留实际完成日期。
- 12 个疾病宣教短片按主题分包，沿用原温和女声和字幕。初次进入某短片需要微信载入该静态分包；之后从本机文件播放。分包或文件被系统清理后可能需要再次载入。
- 吸入器目录保留 27 个产品、装置或附件入口及原视频来源。其中 19 项方法已核对，18 项配置主视频；仍有专属材料缺口，见[来源账本](docs/inhaler-video-sources.md)。第三方网页视频需主动复制链接到手机浏览器观看，没有下载转载，也没有伪造微信内直接播放。
- 保留原有 7 首音乐目录。只有点击播放才联网加载，离开页面停止；联网播放并不上传健康记录。
- 大字模式、减少动效、可选本机报告副本与清除本机资料。

本版本面向患者居家引导，不包含医院网页工作台的全部专业设备记录界面，不连接设备、不自动开具训练负荷或调整药物和氧流量。报告不在小程序中做 OCR，专业数值仍需手工核对。原网页和医院 EXE 继续独立保留。

## 本机数据

| 内容 | 存储位置 | 保存动作 |
| --- | --- | --- |
| 健康评估、每日评估、训练汇总、显示设置 | 微信 `wx.setStorageSync` 本机缓存，独立命名空间 | 明确保存评估、结束或完成训练、修改设置 |
| 主动选择的 PDF、PNG、JPEG 报告副本 | 小程序 `USER_DATA_PATH/hulan-reports/` | 主动选文件并允许相应隐私接口 |
| 宣教短片副本 | 小程序本地文件目录 | 主动打开对应短片并播放 |

没有 `wx.cloud`、健康数据 `wx.request`、`wx.uploadFile`、Socket、用户身份获取、位置获取或统计 SDK。不记录健康信息到控制台日志。文件名和报告原文不会发送到业务服务器。

这里的本机保存不等同于独立加密、永久备份或微信平台不收集任何基础服务信息。微信负责代码分发、平台服务与缓存管理；本应用只控制自身代码的数据行为。更换手机、删除小程序或清理微信存储后，资料可能丢失，不会从服务器恢复。请保留检查材料原件。

保存失败时界面明确显示未保存。损坏、未知版本或超容量的记录不会被自动覆盖或静默删旧。当前限额为 365 条每日记录、500 条训练汇总，结构化记录使用 512 KiB 预算；报告最多 6 份、每份 8 MiB。

“本机数据与设置 → 清除本机资料”需要再次确认，仅清除本应用的健康数据、报告副本和设置。旧评估草稿、旧训练及延迟文件选择回调同步失效，不能在清除后重新写回。不会删除微信聊天中的报告原件，也不调用清除其他应用缓存的接口。静态教学视频不是健康资料，可由微信按缓存策略管理。

## 正式 AppID 配置

- 在 `project.config.json` 中配置运营方自己的 AppID；AppSecret、上传私钥和账号凭据不属于这个前端工程，不能写进项目或 Git。
- 在小程序后台按实际用途配置用户隐私保护指引。相册、拍照和选择文件仅在用户主动点击时调用 `wx.chooseMedia` 或 `wx.chooseMessageFile`，会按微信隐私授权结果执行；配置缺失或用户拒绝时可跳过材料。
- 原有在线音乐需要将 `https://niuontheway-ops.github.io` 配置为适用的下载合法域名，并核对实际播放与版权授权。不要为发布关闭合法域名校验。教学分包不需要自建媒体域名。
- 本应用不需要上传文件域名、业务 request 域名、云开发环境或 web-view 业务域名。
- 小程序名称、医院主体、服务类目和相关资质由运营方在微信后台核实；代码包通过本地检查不代表已经获得微信审核或医疗合规认定。

## 源码维护与检查

以下命令在包含本项目的仓库根目录运行。已经生成的本文件夹可以直接导入开发者工具，重新生成时才需要 Node.js 22+、pnpm 和 FFmpeg/FFprobe。

```shell
pnpm install --frozen-lockfile --ignore-scripts
pnpm build:mini
pnpm test:mini
pnpm check:mini
```

`scripts/build-miniprogram.mjs` 从网页项目选取纯逻辑模块，转换为 CommonJS；兼容 `Object.hasOwn`，使用明确的上海日期计算，排除浏览器 DOM 呈现。医学阈值、分流规则和训练状态机保持原来源逻辑。`app/core/source-manifest.json` 记录输入和输出摘要。

`scripts/build-miniprogram-content.mjs` 从原目录生成本地内容与视频分包。12 个短片转换为 H.264 480×480、20 fps，AAC 音频数据流复制而不重新配音；核对声轨摘要、片长、字幕和体积。可以用 `FFMPEG_PATH`、`FFPROBE_PATH` 指定工具路径。

`pnpm check:mini` 使用固定的微信官方 `miniprogram-compiler` 检查全部 WXML/WXSS；同时检查路由、事件绑定、条件插值、原生组件、代码语法、包大小和意外网络接口。Node 测试模拟原生 API，检查保存失败、危险症状、生命周期、清除竞态及实际编译模板的状态分支，不能替代微信客户端实机验收。
