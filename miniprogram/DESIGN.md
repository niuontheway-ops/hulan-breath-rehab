# 患者小程序设计

使用场景是患者在自己的手机上跟随轻柔呼吸引导、记录当天状态和查阅照护知识。保留正式壶兰呼吸图片及医院科室署名，不重绘品牌标志。配图复用原项目的生活场景素材。

颜色沿用既有系统：背景 `#eef4f0`、内容面 `#fbfcf9`、正文 `#153f3a`、行动色 `#185b50`、辅助正文 `#4e655f`；需要复核与危险状态分别使用带文字的暖黄和深红提示。颜色不会独自表示允许训练或异常。未取得患者数据时显示空记录，不生成疗效分数或虚构趋势。

首页的主要动作是先评估或进入当前训练；下方按任务组织每日评估、康复安排、吸入器与音乐。使用微信原生四项底部导航。评估每步只回答同类问题；训练前状态逐题确认，评分和材料选填。选择与确认有即时状态，按钮使用短促的按压、轻抬反馈，不用持续装饰动画争夺注意力。

个人美学基础规则 B001–B004 用于对比、窄屏重排、操作状态和内容主次；R003/W175 仅用于将环境、主体和焦点色划分为界面的颜色角色，属于独立 UI 迁移，不是原作者提供的医学或小程序规范。B002 的窄屏检查发现单用 rpx 会让 320px 手机的大字退回普通字号，因此大字关键正文改为至少 20px，按钮组在大字模式下纵向排列。

动态人物的嘴形、手和腹部由实际引导时钟驱动；想象楼梯与草地的步数属于引导场景，不冒充传感器观测。暂停、后台或每轮待确认时停止计时与动作。减少动效时保持静态画面，保留阶段文字和倒计时。

布局验收使用实际 WXML 编译后的节点与 WXSS 在独立浏览器中检查，覆盖 375px 普通与 320px 大字状态。它证明模板和样式的相关表现，不代表已经在微信 iOS、Android、鸿蒙客户端完成实机测试。
